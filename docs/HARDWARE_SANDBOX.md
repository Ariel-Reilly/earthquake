## 0. 一句话结论

沙盘不是"模型摆件"，而是**一台物理故障注入器**：地形来自真实 DEM，传感器是真的，
数据以真实量纲灌进生产系统的数据管道，让规则引擎、AI 服务、预警中心、指挥大屏
在**真数据**上跑一遍，而不是在 mock 数据上跑一遍。

## 2. 场景选取：重庆渝中半岛 · 李子坝—佛图关—嘉陵江段

### 2.1 为什么选这一段

| 重庆地灾特征 | 该段是否具备 |

| 山地丘陵、地形高差大 | ✅ 江面 ~160 m → 鹅岭/佛图关 ~360 m，高差约 200 m |
| 红层砂泥岩互层易滑地层 | ✅ 可实体做成分层色岩层 |
| 两江汇流、洪水位威胁 | ✅ 嘉陵江纵贯沙盘北缘 |
| 陡坡上的建成区（"轻轨穿楼"） | ✅ 李子坝台地建筑群 |
| 低洼路网内涝 | ✅ 滨江路低洼段 |
| 危岩崩塌 | ✅ 佛图关陡崖 |

**一段地形同时容纳 4 类灾种**，一套沙盘跑完 4 个剧本。

### 2.2 空间映射（★ 与 DEM 分辨率的权衡）

这里有一个必须先想清楚的矛盾：**要陡峭就要小范围，要有 DEM 分辨率就要大范围。**

- 若沙盘只代表 640 m：真实 30 m 分辨率的 DEM 只有 21×13 个网格点，地形是糊的；
- 若沙盘代表 3 km：DEM 有 ~97×64 个网格点，形态清晰，但坡度被"摊平"。

解法是**扩大范围 + 垂直夸张（VE）**——这也是所有专业地形沙盘的标准做法：

| 项 | 取值 | 说明 |
|---|---|---|
| 真实范围 | 约 2.91 km × 1.93 km | `106.5150,29.5425 ~ 106.5450,29.5600` |
| 沙盘尺寸 | 1200 mm × 800 mm | 桌面级 |
| **水平比尺** | **1 : 2421** | |
| **垂直夸张 VE** | **2.5** | 垂直比尺 1:968 |
| 沙盘起伏 | 约 207 mm（按真实高差 ~200 m 计） | |
| 泡沫分层 | 20 mm × 14 层 | 等高距约 19.4 m |

坐标换算（网关 `config.yaml` 与 `tools/dem_to_foam.py` 共用同一套，务必一致）：

```text
lon = 106.5150 + (x_mm / 1200) × 0.0300
lat = 29.5425 + (y_mm /  800) × 0.0175
```

> VE=2.5 意味着 32° 的真实边坡在沙盘上呈约 55°。汇报时说明"垂直方向做了 2.5 倍夸张以突出地形起伏"，
> 这是制图的通行做法，不是失真——**所有用于规则判定的数值都是真实量纲，不随 VE 改变**。

| 区 | 名称 | 沙盘范围(mm) | 地貌 | 灾种 | 隐患点 |

| **B** | 李子坝岸坡 | x 200–650, y 250–620 | 边坡、砂泥岩互层、可滑动坡体 | `landslide` | `HZ-SBOX-01` |

## 3. 真实地形建模与泡沫加工工艺（核心）

### 3.1 流程总览

```text
真实 DEM  →  裁范围 / 重采样 / 平滑  →  按比尺换算  →  分层轮廓  →  泡沫切割  →  堆叠修坡  →  表面处理
 (GeoTIFF)        dem_to_foam.py           (VE=2.5)      (SVG 图纸)    (刀/热丝/CNC)   (粘结打磨)    (防水着色)
```

### 3.2 DEM 数据源

| 数据源 | 分辨率 | 获取方式 | 评价 |
|---|---|---|---|
| **ALOS AW3D30 / 12.5m** | 12.5–30 m | 地理空间数据云（gscloud.cn），国内可下 | **首选**，中国区域覆盖好 |
| Copernicus DEM GLO-30 | 30 m | 项目已接入 CDSE（`docs/CDSE_SETUP.md`） | **次选**，可复用既有链路 |
| NASADEM / SRTM | 30 / 90 m | NASA Earthdata | 备选，90 m 偏粗 |
| 在线地形瓦片（terrarium） | ~4 m@z15 | `dem_to_foam.py --fetch` | 仅快速粗看，覆盖不稳定 |

> 2.91 km 范围内，30 m DEM 可得约 97×64 个网格点——足以表达山脊、河谷、陡崖的宏观形态。
> 拿到 12.5 m 数据更好，地形细节（冲沟、台地边缘）会更清楚。

### 3.3 泡沫材料选型

| 材料 | 密度 | 特点 | 结论 |
|---|---|---|---|
| **XPS 挤塑板** | 25–40 kg/m³ | 闭孔、强度高、切面细腻、吸水率低、不易掉渣 | ✅ **主体首选** |
| EPS 聚苯板 | 12–20 kg/m³ | 轻、便宜，但颗粒粗、易掉渣、强度低 | 仅用于填充/粗略大块 |
| 高密度 EPS 雕刻板 | 20–30 kg/m³ | 专为雕刻设计，切面较细腻 | CNC 雕刻时首选 |
| PU 发泡板 | 30–200 kg/m³ | 强度高但贵、难加工 | 仅局部需要高强度时 |

**采购建议**：

- 板材标准尺寸多为 **1200 × 600 mm**。若沙盘深度取 **600 mm** 可实现零浪费；
  取 800 mm 则每层需拼接（600 + 200），损耗约 5%，换来更好的视觉纵深——**建议取 800**。
- 厚度 **20 mm**（XPS 最常规），14 层堆叠；想要更细腻可上 15 mm（EPS）约 19 层。
- 备料按工具输出的合计面积 × **1.3**（拼接损耗 + 切废 + 返工）。

### 3.4 加工工艺（三选一）

#### 方案 A：分层堆叠法 ★ 推荐

`dem_to_foam.py` 默认输出的就是这套图纸。

1. 工具按等高距把 DEM 切成 N 层，每层输出一张轮廓 SVG（mm 单位，1:1 可打印）；
2. 图纸打印（或描到泡沫板上）→ 手工刀 / 电热刀 / 线锯沿线切割；
3. 自底向上逐层粘结，形成阶梯状地形；
4. 重点区域（B 区坡面）抹灰修圆，其余保留阶梯。

**优点**：零设备门槛、成本最低、工期可控；**阶梯状断面天然就是岩层层理**，
配合分层配色可直接表现重庆红层砂泥岩互层——这是本方案最讨巧的一点。

#### 方案 B：热丝切割

用电热丝（镍铬丝 + 调压电源）沿模板切割，适合切**贯通的直纹曲面**（如河岸边坡）。
切割速度快、无粉尘，但只能切直纹面，复杂地形仍需与方案 A 配合。

#### 方案 C：CNC 铣削

整块厚 XPS 块料上机，按 `dem_to_foam.py --stl` 导出的 STL 铣削出连续曲面。
精度最高、表面最光滑，但需外协加工（费用 ¥1,500–3,000），工期受外部排期影响。

> **推荐组合**：A 为主（做主体与岩层），B 用于河岸等长直纹面，C 视预算可选。

### 3.5 分层切割图生成工具

```bash
# 无 DEM 时先用合成地形验证脚本（离线自检）
python tools/dem_to_foam.py --synthetic --out ./out

# 真实 DEM（ASCII Grid，零额外依赖）
python tools/dem_to_foam.py --dem chongqing.asc --out ./out

# 真实 DEM（GeoTIFF，需 pip install rasterio）
python tools/dem_to_foam.py --dem chongqing.tif --bbox 106.515 29.5425 106.545 29.56 --out ./out

# 调整参数：板厚 / 垂直夸张 / 网格精度 / 导出 STL
python tools/dem_to_foam.py --dem chongqing.asc --layer-mm 20 --ve 2.5 --grid-mm 2 --stl
```

输出：

| 文件 | 用途 |
|---|---|
| `layers/L01_z87m.svg` … | 每层切割图纸（mm 单位，可打印/描线/送绘图仪） |
| `layer_table.csv` | 层号 / 阈值高程 / 板厚 / 累计高度 / 岩性 / 配色 / 轮廓面积 / 是否整块板 |
| `preview.html` | 浏览器打开即可检查分层叠加效果与地形合理性 |
| `terrain.stl`（`--stl`） | 3D 打印 / CNC 铣削备选 |

自检输出示例（合成地形）：

```text
[INFO] 高程范围 87.0 ~ 356.4 m（高差 269.3 m）
[INFO] 水平比尺 1:2421   垂直比尺 1:968（VE=2.5）
[INFO] 沙盘起伏 278.1 mm
[INFO] 共 14 层 × 20.0mm，等高距 19.4 m
[INFO] 堆叠总高 280.0mm，顶部富余 1.9mm（打磨/垫片吸收）
[INFO] 泡沫板合计面积约 63202 cm² （≈ 6.32 m²，建议按 1.3 倍备料）
```

**验收要点**：层表里"轮廓面积"必须自底向上单调递减（L01 满铺 → 顶层最小）。
若不递减，说明 DEM 有异常值或平滑不足，先用 `--smooth 2` 再跑。

### 3.6 岩性分层配色（重庆红层）

工具内置 4 色循环，自底向上模拟侏罗系沙溪庙组**砂泥岩互层**，顶层为第四系覆盖层：

| 序号 | 岩性 | 色值 | 说明 |
|---|---|---|---|
| 1 | 泥岩夹粉砂岩 | `#7E4433` | 相对软弱，易形成滑动面 |
| 2 | 砂岩 | `#B5836A` | 透水层 |
| 3 | 泥岩 | `#8A4F3C` | 隔水层 |
| 4 | 砂岩厚层 | `#C09176` | 陡崖主体 |
| 顶层 | 第四系覆盖层 | `#9C7A4E` | 表层土 |

阶梯断面按此配色上色后，砂泥岩互层一目了然——
**可以直接指着断面讲"为什么重庆这种地层容易滑坡"**，汇报效果远超纯外观模型。

### 3.7 粘结与表面处理（★ 泡沫很容易被"胶水毁掉"）

| 环节 | 可用 | **禁用** |
|---|---|---|
| 粘结 | 白乳胶（PVA）、泡沫专用胶、低温热熔胶、聚氨酯泡沫胶 | ❌ 502 / 万能胶 / 环氧树脂（含溶剂，会**溶解泡沫**） |
| 批灰 | 白乳胶 + 滑石粉/腻子粉调成的轻质腻子、石膏 | ❌ 含香蕉水/丙酮的腻子 |
| 着色 | 丙烯颜料、水性漆 | ❌ 硝基漆、油性喷漆（溶剂腐蚀） |
| 防水 | 水性聚氨酯 / 丙烯酸防水涂料 | ❌ 溶剂型防水剂 |

工艺流程：

1. 堆叠粘结 → 重物压实 24 h；
2. 修坡：电热刀粗修 + 砂纸/钢丝绒细修（**戴口罩**，泡沫粉尘细小）；
3. 封闭底：白乳胶 : 水 ≈ 1 : 1 刷 2 遍，干透后表面结膜，后续涂层才不会渗进泡沫；
4. 批灰找平（薄层，仅重点区）；
5. 丙烯着色 + 岩层断面分色；
6. 水性防水罩面 2 遍；
7. 河道区单独做**聚氨酯防水 + 玻璃钢衬层**，做 24 h 闭水试验。

### 3.8 加工安全

| 风险 | 措施 |
|---|---|
| ❌ **禁止激光切割泡沫** | 会熔化、产生大量苯乙烯等有害气体，且切面焦糊无法使用 |
| 热熔/热丝切割烟气 | 必须通风，佩戴防有机气体口罩（活性炭滤盒） |
| 泡沫粉尘 | 打磨时戴防尘口罩，湿式作业优先 |
| 电热刀/热丝烫伤与火灾 | 远离泡沫堆放区，断电后人离，配备灭火器 |
| 胶粘剂挥发 | 选水性胶，作业区通风 |

### 3.9 沙盘要素制作：山体 / 水体 / 山路 / 建筑

地形之外的四类要素，做法与真实数据的对应关系如下。
所有地物位置都由 OSM 真实数据换算（见 §3.10），不是随手摆放。

| 要素 | 实体做法 | 材料与规格 | 关键注意 |
|---|---|---|---|
| **山体** | XPS 分层堆叠（同 §3.4） | 20 mm 板 × 14~16 层 | 沙盘版实测起伏 0.329 m → **16 层 × 20 mm** |
| **水体**（嘉陵江/长江） | 河床挖至设计高程 → 铺蓝色片材 | 0.5 mm 哑光蓝 PVC/亚克力 + 水性防水涂料 | ★ 水面必须比周边泡沫**低 3~5 mm** 形成岸线，否则水会溢出盘外 |
| **水体**（动态演示） | 河槽防水后接微型潜水泵 | 已在 ESP32 固件预留 `pump` 执行器 | 水位由 `WS-RIVER-01` 实测，不是假数据 |
| **内涝点**（D 区） | 低洼处预留浅槽，注射器定量注水 | — | 积水深度由 `SB-FLOOD-01` 实测 |
| **城市道路** | 按 OSM 中心线裁剪贴片 | 0.5 mm 灰/深灰卡纸或 PVC 片 | 1:2421 下主干道仅 ~10 mm，可按 ×2 放大以便观看 |
| **山路/梯道** | 3 mm 泡沫薄条**逐级错位粘贴**成踏步；或坡面刻槽填石膏 | XPS 薄片 / 石膏 | ★ 本区 OSM 有 **198 条** footway/steps（重庆梯道），是山城辨识度的关键，建议必做 |
| **建筑 · 城市** | EPS 小块按 footprint 切割 | 高度按真实层数 × 3 m 换算 | 30 层 ≈ 37 mm，可辨识；固定用牙签 + 白乳胶 |
| **建筑 · 公共** | 同城市做法，单独配色作地标 | 医院/学校/车站 | 沙盘解说时的定位锚点 |
| **建筑 · 乡村** | 泡沫小块 + 两片斜切泡沫粘坡屋顶 | XPS + 细砂纸打磨 | 瓦面用哑光色，避免反光干扰摄像头识别 |

> ★ **比尺提醒**：建筑高度与路宽按**水平比尺**（1:2421），地形起伏用 **VE=2.5** 夸张，
> 两者比尺不同是沙盘惯例。解说时务必说明，否则观众会把楼高误判为真实高度的 2.5 倍。
> 生成器已按此约定实现（垂直夸张只作用于地形，见 `build_revit_model.py`）。

> ★ **禁用**：502 / 溶剂型胶 / 硝基漆会溶解泡沫（同 §3.7），建筑与道路粘贴一律用
> **水性白乳胶**或 **UHU por**（泡沫专用）。

**配套加工图纸**（`tools/osm_to_foam_parts.py` 生成）。
坐标系与地形分层图 `layers/*.svg` **完全一致**，可打印在透明胶片上直接叠加定位：

| 图纸 | 内容 |
|---|---|
| `A_buildings_map.svg` | 建筑平面位置（真实 footprint + 编号） |
| `A2_building_parts.svg` | 建筑立面下料排版（每栋宽 × 高，1:1 照切） |
| `B_roads.svg` | 道路与梯道贴片裁剪（山路/梯道单独配色） |
| `C_water.svg` | 水体开挖轮廓 + 水位标注 |
| `D_assembly.svg` | 总装定位：网格 + 设备点位 + 建筑 + 道路 + 水体 |
| `parts_list.csv` | 零件清单（编号 / 尺寸 mm / 材料 / 配色） |

本区实测：建筑 **247 栋**（中位 14.7 × 11.2 × 10.7 mm，最小边已按 2.5 mm 过滤）、
道路 **535 条**、乡村民居 **40 座**、水体 **15 环**（水面占盘面 **24.1%**）。

**关于 `.rvt`**：`.rvt` 是 Autodesk 专有二进制格式，任何脚本都无法直接生成。
工具输出 **IFC4** —— Revit 原生打开格式，「打开 `model.ifc`」后「另存为」即得 `.rvt`。
另附 `terrain_points.csv`，可用「体量和场地 → 地形表面 → 通过导入创建 → 指定点文件」
单独建地形（但该方式不会带入水体/道路/建筑）。

**已踩过的坑（工具内已处理）**：

1. `waterway=river` 在 OSM 里是**中心线**（LineString）不是面，直接栅格化只会得到一条细线。
   河谷形态改用 DEM 判据，中心线仅用于标注河名（本区确认为嘉陵江、长江）。
2. Overpass 返回的是**完整** way（只要与 bbox 相交就整条返回），顶点常远在场地之外，
   导致包围盒被撑到 X −5032~4874 m。已做折线拆分与跨界要素剔除。
3. 地形瓦片含约 0.13% 的 NoData 坏像素（−9728 m 量级），不清洗会把高差拉成 4000 m，
   等高线、泡沫分层、Revit 点文件全部失效。`dem_to_foam.sanitize()` 已做邻域填充。
4. 瓦片覆盖范围大于 bbox，不裁剪会整体错位约 10%。已按 bbox 精确裁剪。

## 4. 相似律与标定

### 4.1 三个必须承认的近似

| 项 | 处理 | 理由 |
|---|---|---|
| **几何** | 水平 1:2421，垂直 VE=2.5 | 兼顾 DEM 分辨率与视觉起伏 |
| **位移/裂缝** | **放大映射**：沙盘 1 mm = 真实 10 mm | 真实 5 mm/h 位移按几何缩尺后是 0.002 mm/h，任何传感器都测不到。物理沙盘通行做法是放弃力学相似、保留因果链相似 |
| **时间** | **压缩 360×**：演示 4 min = 真实 24 h | 否则一次演示要等一天 |

> 被问到"这符合相似律吗"时的标准回答：
> **本沙盘验证的是信息链路与决策逻辑，不是岩土力学过程。**
> 物理量纲、阈值、因果顺序与生产环境完全一致；放大系数写在 `gateway/config.yaml` 里、可审计。

### 4.2 标定公式

| 上报指标 | 沙盘原始量 | 换算 |
|---|---|---|
| `rainfall_24h` | 翻斗脉冲 N | `N × 0.5 mm × rain_gain` |
| `soil_moisture` | 电容 ADC | 干/湿两点标定后线性插值 → % |
| `displacement_total` | 激光测距 Δd mm | `Δd × disp_gain`（=10） |
| `displacement_rate` | Δd mm / Δt s（沙盘） | `Δd × disp_gain × 3600 / (Δt × time_compress)` mm/h |
| `crack_width` | 电位器 ADC | `Δmm × crack_gain` |
| `crack_width_rate` | Δmm / Δt | `Δ × crack_gain × 86400 / (Δt × time_compress)` mm/day |
| `tilt_angle` | MPU6050 俯仰角 | 直接使用（°），角度不缩放 |
| `water_level` | 超声波水深 h mm | `160.0 + h/80 × 20.0` m |
| `warning_level` | 常量 | `175.0` m |
| `slope` | 常量 | `32.0` ° |
| `ponding_depth` | 电极/测距 | 查表 → cm |

### 4.3 时间压缩下的降雨实现

真实 80 mm/24 h 压缩到 4 min，等效雨强 20 mm/min。全沙盘喷淋需 ~19 L/min（不现实），
**收敛到只喷淋 B 区坡体（约 0.16 m²）→ 3.2 L/min**，12 V 潜水泵可满足。

雨量计量保留**真实翻斗式雨量计**（0.5 mm/斗），喷淋口正上方设承雨漏斗；
网关按脉冲真实累积，同时用**比例闭环**调节水泵占空比使累积曲线跟随剧本目标值——
**既真测量，又可控节奏**。

## 7. 数据接入契约（接进现有平台的硬约束）

> 以下 6 条是从 `DeviceDataService` / `RuleEngineScheduler` / `MqttDataSubscriber`
> 源码逐条核对出来的，**违反任意一条都会导致"数据进去了但预警不来"**。

### 7.1 MQTT 通道

| 项 | 值 |
|---|---|
| Broker | `tcp://<宿主机IP>:11883`（EMQX，容器 1883 映射） |
| Topic | `disasterguard/{deviceCode}/data` |
| QoS | 1 |
| Payload | `{"ts": 1758345600000, "metrics": {"rainfall_24h": 82.5, ...}}` |

`ts` 支持 `ts` / `recordedAt` / `timestamp` 三种键名，毫秒时间戳；缺省用服务端 `now()`。

### 7.2 约束清单（★ 为必踩坑点）

1. ★ **设备必须先注册且 `hazard_code` 非空**
   `RuleEngineScheduler.doEvaluate()` 里 `hazard == null` 的指标直接丢弃。
   未绑定隐患点的设备只入库、不研判。

2. ★ ★ **必须上报"哨兵指标"（本方案第一大坑）**
   规则评估前有门控：`if (!metrics.containsKey(rule.getMetricCode())) continue;`
   而 `warning_rule.metric_code` 是**组合键**，不是真实物理量：

   | 规则 | 表达式 | 门控哨兵指标 |
   |---|---|---|
   | R001 滑坡黄 | `rainfall_24h > 50 AND slope > 30` | **`rainfall_24h_slope`** |
   | R002 滑坡橙 | `rainfall_24h > 80 AND displacement_rate > 5` | **`rainfall_24h_disp`** |
   | R003 洪水红 | `water_level > warning_level AND rainfall_6h > 100` | **`water_level_rain6h`** |
   | R006 崩塌黄 | `crack_width_rate > 2.0 AND rainfall_24h > 30` | **`crack_rate_rain`** |

   → **只上报 `rainfall_24h` 和 `displacement_rate`，R002 永远不触发。**
   网关必须额外发一个 `rainfall_24h_disp` 作为"开门钥匙"（取值任意，本方案用 1.0）。

3. ★ **同一隐患点下，同一 `metric_code` 只能由一台设备上报**
   `hazardMetrics.put(metricCode, value)` 会互相覆盖，顺序取决于
   `DISTINCT ON (device_code, metric_code)` 的返回顺序 → 结果**不确定**。

4. ★ **同一 `(ruleCode, hazardCode)` 存在未关闭预警时不会重复触发**
   → 每次演示前必须归档上一轮预警，否则第二次演示"哑火"。
   `tools/register_devices.py --reset-warnings` 已封装该清理。

5. **时间戳去重**：`(device_code, metric_code, recorded_at)` 唯一索引，
   同一毫秒重发会被静默丢弃 → 上报间隔 ≥ 1 s，时间戳用毫秒。

6. **`rainfall_24h` 是"最新上报值"而非窗口聚合**
   （`findLatestByDeviceCodes` 取每个 `(device, metric)` 的最新一条）
   → 时间压缩方案成立，网关侧累积后直接上报即可。**这一条是沙盘可行的前提。**

### 7.3 演示期参数调整

```yaml
# backend application.yml（仅演示环境）
disasterguard:
  warning:
    rule-engine-cron: "*/5 * * * * *"   # 默认 30s，演示期收紧到 5s
```

## 11. 风险与规避

| 风险 | 影响 | 规避措施 |
|---|---|---|
| ★ **哨兵指标漏发，预警不来** | 高——演示直接哑火 | 网关内置注入；`selftest.py` 专项校验（已实现） |
| ★ **二次演示不触发** | 高 | 演示前强制跑 `--reset-warnings`，纳入检查单 |
| ★ **漏水导致短路/触电** | 高——12 V 与市电共存 | 12 V 隔离供电 + 漏电保护；双层防水；电气仓与湿区隔离；24 h 闭水试验 |
| ★ **胶水/涂料溶解泡沫** | 高——地形报废 | 只用 PVA 白乳胶、丙烯、水性涂料；**禁用 502/万能胶/硝基漆**；废料先试 |
| 泡沫激光切割中毒 | 高 | **明令禁止激光切割**，改用刀/热丝/CNC；热丝作业强通风 + 防有机气体口罩 |
| DEM 分辨率不足 | 中 | 优先 12.5 m ALOS；30 m 时用 `--smooth` 抑制锯齿；必要时缩小 VE |
| 垂直夸张被质疑 | 中 | 明确"仅几何夸张，判定数值仍是真实量纲"，配置可审计 |
| WiFi 拥塞（展会展厅） | 中 | 网关与 ESP32 走独立热点，后端本地部署，不通外网也能跑 |
| 时钟漂移导致去重误吞 | 中 | 网关统一发 `ts`，本地 NTP 校时；间隔 ≥ 1 s |
| 传感器标定漂移 | 中 | 每次演示前跑干/湿两点复标 |
| 后端 30 s 调度太慢 | 中 | 演示期 cron 改 5 s |
| 沙盘霉变（长期湿） | 低 | 演示后吹干，坡体填料可更换 |

## 13. 与其他方案的边界

- 本方案**不改动任何后端业务代码**，仅建议演示期调 1 个 cron 参数；
- 沙盘数据进入的是**生产同一套表**（`device_metric` / `warning_event`），
  因此演示后建议用 `--reset-warnings` 清理，或用独立演示库隔离；
- 沙盘设备统一前缀 `SB-` / `WS-`，便于一键清理；隐患点统一前缀 `HZ-SBOX-`。
