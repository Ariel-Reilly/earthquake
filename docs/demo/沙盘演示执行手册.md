## 2. S1 360 秒彩排脚本（D2 全文）

### 2.0 启动与计时（不改代码，只加运行参数）

```powershell
ai-service/.venv/Scripts/python.exe scripts/demo/sandbox_e2e.py --check
ai-service/.venv/Scripts/python.exe scripts/demo/sandbox_e2e.py --scenario s1 --steps 185 --interval 2.0 --reset
```

**必须显式 `--steps 185`**：`sandbox_e2e.py` 的 `main()` 中 `s1` 缺省 165 步，×2s 只到 **330s**，会砍掉 360s 的降级解除。185 步 = 370s，覆盖完整 360s 并留 10s 余量。`--interval 2.0` 与默认值一致，显式写出便于秒表对齐。这是命令行参数，未动后端、规则、网关 serial 模式或 `config.yaml`。源码依据：`sandbox_e2e.py:399-436`（`main()`）、`sandbox_e2e.py:272-344`（`run()` 为 `while proc.poll() is None`，无独立超时，网关按 `--steps` 自行退出）——本轮已现场核过源码，非按记忆。

- **T0**：终端打印 `[RUN] 剧本 s1` 起启动秒表；助手 B 每 30s 报点。
- **容差**：网关 `demo_sec` 起点比演练脚本计时早约 1s，叠加 2s 上报间隔 + 5s 规则调度，屏幕时点允许 **±10s**。
- **剧本是线性插值**（`scenario_player.py` 的 `Scenario._interp()`）：R001 的 50mm 在约 179s 越过、R002 的 80mm 在约 270s 越过，因此黄警实际弹窗约 **180–205s**、橙警约 **272–290s**。**现场灯光动作按方案 A 跟随屏幕报点**，泵档位与 SG90 仍严格按 200s / 280s 起的计划节奏、不提前。

### 2.1 角色分工与动作属性

| 角色 | 职责 |
|---|---|
| **主讲** | 只讲解、指屏，不碰面板 |
| **助手 A（面板位）** | 水泵继电器/档位、SG90 点动、灯带切色、蜂鸣器——全部为**人工面板操作** |
| **助手 B（确认位）** | 盯终端与大屏、报 30s 点、在 0/200/280/300/360s 逐项报「确认项」、截图录像，兼 360s 降级/解除按钮操作 |

**提前置位（演示前 10 分钟完成，不占 360s）**：水槽水位 15–20cm、滴头滴速、喷淋角度、坡体复位、灯带/蜂鸣器通电自检、两板共地、大屏预警页与指挥页打开、`--check` 通过、`--reset` 完成、录像开录。

**必须实时按**：0s 开泵、30/90/150/200/240/300/330/360s 泵档位、200s 首次点动 SG90、黄警报点切黄 + 蜂鸣器、280s 切橙 + 加速推进、300s 全行程、360s 停泵/复位/熄灯。

**单人备选（修订版，不依赖任何额外设备）**：助手 A 与助手 B 由同一人兼任时，把实时动作压到 **4 个**（① 0s 开泵；② 黄警报点切灯并点动 SG90 一次；③ 橙警报点切灯并把 SG90 推到全行程；④ 360s 停泵/复位/熄灯），其余泵档位微调与蜂鸣器全部提前置位或省略。单人模式下 SG90 首推合并到报点属**演示降级**，不影响 R001/R002，但**不能完整复现双人版节奏**。

### 2.2 报点规则（方案 A，已定稿）

助手 B 在大屏看到黄/橙预警弹窗的**那一刻立即报点**，不等 200s/280s；助手 A 听到报点**立即切灯带颜色并短响蜂鸣器**，这是唯一跟随报点的动作。主表中 200s / 280s 的「切黄 / 切橙」为**计划动作时间，实际以屏幕报点为准，允许提前至 180s / 270s**；泵档位与 SG90 仍严格按 30s 主表节奏、不因报点提前（200s 首次点动、280s 加速、300s 全行程不变），以保住「0–200s 坡体静止、不提前推坡体」。时间差由 §2.4 兜底话术覆盖，主讲听到报点即可顺势讲「预警已由平台生成，现场灯光同步展示」。彩排前三人对照一次本条款。

## 4. 对外口径与答辩话术（D4 全文）

**三句话口径（主讲背诵，三人统一）**

1. **演示模式**：本轮采用 **scenario 剧本编排模式**，由 `sandbox_e2e.py --scenario s1 --reset` 把 S1 标定工况送入生产数据管道，规则引擎按既定阈值自动研判并发布预警，走完 360 秒业务闭环。
2. **硬件角色**：实体沙盘、ESP32、水泵、舵机、灯带、蜂鸣器承担**视觉与听觉呈现**；传感器可现场展示真实采集，但读数**不参与 R001/R002 判据**，执行器为**现场人工面板操作**，非系统下发。
3. **真实采集链路定位**：`serial` 采集链路已实现，本轮为节奏确定性采用 scenario；`serial` 模式下与 R001/R002 的判据适配、以及真实数值驱动预警，属**后续叠加，当前不承诺**。

**预判两问（各一句，不回避、不承诺）**

- **「数值是真实的吗」**：「数值是剧本编排的标定工况（真实量纲、按演示节奏压缩的标定过程），进的是生产同一套表和规则引擎，预警由规则引擎按阈值自动研判产生，不是预置结果；现场传感器读数是另一路展示，不参与判定。」
- **「识别在哪」**：「视觉识别为后续叠加，本轮以业务闭环（接入→研判→预警→应急指挥→降级解除）为主，摄像头只提供大屏实时画面，不承诺识别框。」
