# D1 · ESP32 接线表（2 节点版）

> 附件：接线时单独打印。主文件见 [沙盘演示执行手册](./沙盘演示执行手册.md)。
> 行号基于 commit `e4a73e7`，代码变动后以函数名 / 宏名为准，不要依赖行号。
> 本轮策略：**scenario 为主，硬件做视觉**。不改代码、不改 `config.yaml`、不新增采购，BOM ¥787.4 不变。

## 接线前提（不展开）

`scenario` 模式下网关只读 `scenario_player`、不读串口，执行器指令走 MQTT `disasterguard/sandbox/cmd` 而非串口，因此 ESP32 的采集值与控制指令都不进入 R001/R002 链路。下表「必接」仅指**现场可见性 / 讲解需要**，不代表参与判据；泵、舵机、灯带、蜂鸣器一律按主文件 §2 彩排脚本由现场人工操作。也正因如此，2 节点版不会触发 Node-C 缺失问题。

## 供电预算（5V/5A = 25W）

| 负载 | 常态 | 峰值 |
|---|---|---|
| ESP32 ×2（USB） | ~2W | ~4W |
| 5V 水泵 | ~5W | ~6W |
| SG90 ×1 | ~1W | ~3W（堵转） |
| WS2812B（演示限亮）+ 蜂鸣器 | ~2W | ~2.5W |
| 继电器线圈 | ~0.4W | ~0.4W |
| **合计** | **~10W** | **~16W** |

5V/5A 有约 9W 裕量；**所有 5V 地线与两块 ESP32 共地一次**，避免电位差。12V 器件不并入此路。

## 引脚冲突 / 红线自检（7 条）

1. **`GPIO21` 复用**：Node-A 上 `PIN_WATER2_ECHO=21` 与 `Wire` 默认 SDA 同脚 → 本版不接超声波 #2、保留 BME280，冲突消除。
2. **`GPIO32/33` 复用**：原 Node-C 裂缝计与 Node-B 土壤湿度同编号 → 2 节点版无 Node-C，天然无冲突（这是选 2 节点版的直接收益）。
3. **ADC 脚只输入**：`34/35/32/33/25` 不得驱动任何负载；`GPIO2` 已占板载 LED，灯带数据线另走人工控制器。
4. **两块板都会把执行器引脚配成输出**（`setup()` 无条件 `pinMode`）→ 执行器**只接一块或本轮全不接 ESP32**，绝不两板并接同一负载。
5. **Echo 电平**：5V 超声波 Echo 需降到 3.3V 才安全；选接项不接时无此要求。
6. **`GPIO12` strapping**：舵机信号不得上电即高；本轮舵机不经 ESP32，无风险。
7. 烧录时若要用串口监视器展示真实读数，按 `esp32_node.ino` 的既有开关把 `SIMULATE_SENSORS` 置 0 即可（烧录选项，仓库代码不动）；scenario 模式下该读数仅本地可见，不进链路。

## D1 验收对照

- 拿到表可直接接线：引脚、供电、接点逐行给出。
- 无引脚冲突：上述 7 条逐项规避。
- 无供电不足：5V 路峰值 ~16W < 25W，12V 器件隔离在外。
- 未夹带未授权改动：未动后端、规则、网关 serial 模式、`config.yaml`，未新增采购项。

## D1 遗留 4 项处置（已在 D2/D3 结清）

1. **BME280 `0x76` vs `0x77`**：固件不改；到货跑 I2C 扫描；讲解词不把温湿度设为看点 → 主文件 §3 表 A 的 A1。
2. **执行器全部人工控制的操作人** → 主文件 §2 角色分工 + 单人备选（4 个实时动作 + 其余提前置位）。
3. **共地方式**：首选两板同插同一台笔记本 USB，地通过 USB 自然共、无需额外线；若一块插充电头、一块插笔记本，用一根杜邦线连两板 GND（BOM 内已有）→ 主文件 §3 表 A 的 A2。
4. **对外口径提前统一**：ESP32 采集值不进 R001/R002 链路、执行器不由系统控制 → 主文件 §4。
